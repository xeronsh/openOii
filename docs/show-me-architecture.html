resumability 的四个 durable 机制

checkpointsengine_checkpoints
  • 按 (run_id, stage) 主键存 state_json
  • resume 从 checkpoint 推起点；全量 run 先 clearCheckpoints
  • critic 回退时 invalidateCheckpointsFrom(stage) 清掉下游
stage attemptsengine_stage_attempts
  • at-least-once，不假装 exactly-once
  • 副作用之前记录 input_hash + idempotency_key
  • resume 复用同一 operation identity，provider_request_id 落库
fencing leaseagentrun.lease_token
  • TTL 120s，心跳 30s，ownerId = engine-{pid}-{uuid}
  • 每个阶段边界 assertExecutionFence()
  • 失去 lease 的旧 executor 立即停手 → 防双写
durable eventsengine_run_events
  • 单调 seq，是 WS replay 的唯一依据
  • 客户端 sessionStorage 存 cursor，断线带 ?after=
  • WS 只是提醒，状态真相在表里
APPROVAL GATE 的跨进程握手
pi 停在 gate → 写 agentrun.awaiting_payload + 置 confirm_requested → 后端 wait_for_confirm_signal() 每 0.3s 轮询（run_signals.py）→ 用户点确认 → 写回列 → pi 继续。这是唯一的 gate 协议，超时 1800s。
为什么 pi 是唯一 Runtime
Anthropic《Building Effective Agents》：最成功的实现用简单可组合模式，而非复杂框架。Cognition《Don't Build Multi-Agents》：单线程线性 agent 是默认架构。多 agent 在本仓库的实际形态是「同一批 agent 两份实现靠口头 parity 维持同步」，不是协作。

ADR 0008 约束正文

  • 禁止在 FastAPI 层重新实现 Agent Loop / Planner / Tool orchestration / Subagent orchestration
  • FastAPI 只有两个身份：Product Backend 与 Pi Runtime 的 northbound gateway
  • 合法职责：鉴权 · 校验 · schema 契约 · ownership 与持久化 · HTTP/WSS 端点 · 转发给 pi · 把 pi 事件翻译成客户端契约
  • 编排决策全归 pi：阶段推进 · agent 选择 · 工具调用 · 子 agent 扇出 · 重试 · 恢复 · 失效计划执行
